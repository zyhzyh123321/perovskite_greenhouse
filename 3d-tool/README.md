# 半透明光伏温室 · 交互原型 v0.3（三天原型）

单页静态应用：左边调参数，中间看温室三维场景，右边看曲线与 Pareto 图，底部是作物视角与同源校验。
**全站标注“基于模型，非实测”**；没有实测曲线时显示“无实测数据”，不编造曲线。

## v0.3 变更

- **屋面重建**：改用四边形顶点直接构造（檐口 3.2 m、屋脊 5.0 m），不再依赖旋转正负号；覆盖板沿屋面法线抬 5 cm，坡向与框架一致，不会再出现“中间低、两边高”。
- **带隙 1.20–2.40 eV、覆盖比 0–1.00**；高带隙提示“进入叠层顶电池区”，高覆盖比提示“接近全遮盖”。

## v0.2 变更（按反馈）

- **盖板方向修复**：面板改为双面材质，并沿屋面法线外移 6 cm，避免与玻璃共面；法线朝上、不再“上下颠倒”。
- **白天场景**：天蓝渐变穹顶、暖色太阳光、草地色地面、雾距拉远；曝光仍锁定（滑杆变动不会让颜色跟着漂）。
- **滑杆范围加大**：Eg 1.45–1.85、厚度 20–500 nm、陡边 2–80 nm、覆盖比 0–0.60。
- **越界提示**：超出“已验证/可实现”范围时，读数变**琥珀色**并给出原因（如“覆盖比 >0.35：超出已验证部署窗口”）。
  **红色仍只用于数据冲突**（哈希不一致、校验失败），不用于越界或不可行——否则红色会同时代表“算错了”和“不可行”。
  作物不可行仍用灰底斜纹。

## 打开方式

三种，按方便程度排：

1. **单文件版（纯前端、双击即开）**：`dist/greenhouse-single.html`，约 1.6 MB，双击用浏览器打开即可，不需要任何服务、可离线、可拷贝给别人。构建命令：`node tools/build-single.mjs`（先 `esbuild` 打包一次，见下）。
2. **已运行的本地服务**：浏览器打开 `http://127.0.0.1:8765/`（后台任务 `pwsh-9302ae4c46be44c0`）。
3. **重新起服务**：双击 `serve.cmd`（本地 http.server，端口 8765）。

> 说明：应用本身是**纯前端**，没有任何后端逻辑。只有“多文件版”需要一个静态文件服务，是因为浏览器不允许 `file://` 下加载 ES module；单文件版把脚本内联了，所以能直接双击。

重新构建单文件版：

```
node node_modules/esbuild/bin/esbuild src/main.js --bundle --format=iife --minify --target=es2020 --outfile=dist/app.js
node tools/build-single.mjs
```

## 界面

- **预设**：P1 高效 / P2 高透 / P4 叠层（标 `out_of_gate`）/ P5 中性（可制造）；P3 是理想上界参照，点击会提示“不可制造”，不可作为设计点。
- **滑杆**：带隙 Eg、吸收层厚度 d、近红外管理强度、第二层陡边宽度 w、覆盖比 f；作物与季节下拉。
- **三维**：单栋玻璃温室，覆盖带长度随 f 变化；板色与室内主光由**同一条 T(λ)** 算出（CIE 1931 → sRGB，线性空间、锁定曝光）。
- **图表**：透射曲线（标出红/远红窗）、Pareto（只画有实测 PCE 的预设；无实测的不进图）、与空白玻璃对比。
- **作物视角**：两行并列——冠层平均 / 阵列正下方（DLI、R:FR、PSS、形态方向）；品质只给“方向未验”。
- **不可行**：灰底斜纹覆盖，只给原因码、差多少、最近可行点；**不出现任何产量数值**。
- **同源校验**：面板/图表/渲染三处共用曲线指纹（16 位哈希）；状态里不存裸数字。

## 已自动验收（`node tools/verify.mjs`，13/13 通过）

- B 同源：指纹稳定、颜色重复一致、hex 合法；
- C 边界：冬季叶菜不可行（DLI 8.3 < 12）、夏季可行、不可行不给代价、DLI 随 f 单调、f=0 时 R:FR 回到自然值 1.097；
- 预设排序：P1 富远红（FR/PAR 2.61）> P3 接近中性（1.11）> P4 缺远红（0.92）；
- D 离线：无 CDN 引用、本地 three/echarts 存在。

## 未完成 / 已知限制

1. **视觉检查未在浏览器里自动跑**：本机沙箱拒绝 Edge 无头启动（`OpenProcess: 拒绝访问`），所以三维构图、配色与排版未做截图核对，需要你打开页面看一眼。逻辑与资源加载已全部通过。
2. **物理是参数化近似**（E2）：带隙—带边蓝移、吸收边宽度都是经验参数，AVT/FR‑PAR/R:FR 与光学侧详细模型可能差 10–30%；界面已标“模型”，不参与任何结论。
3. **没有实测曲线**：P2/P5/P3 的 PCE 为“无实测”，因此不进 Pareto；这是正确行为。
4. **性能预算未测**：帧时间、长任务需在真实浏览器里用 PerformanceObserver 跑（原计划的验收 A）。
5. 三维场景是示意，不是照片级；作物为实例化几何体，不做生长形态。
